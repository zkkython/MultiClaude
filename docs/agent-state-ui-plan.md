# Agent 状态丰富管理 UI 方案（Claude/Codex）

## 1. 背景与目标
当前多 Terminal 并行时，用户难以快速识别哪些会话需要人工介入。  
目标是在保持界面简洁美观的前提下，建立“可行动优先”的状态视图，让用户最快定位 `needs input` 会话并处理。

核心目标：
- 快速发现需要人工干预的 Terminal
- 一键/快捷键跳转待处理会话
- 不增加 UI 噪音，不破坏现有极简风格

---

## 2. 设计原则
- 可行动优先：`waiting`（需人工）优先级最高
- 低噪音默认：常驻信息最少，详细信息渐进展示
- 全局入口统一：底部 StatusBar 做“上帝视角”主入口
- 交互最短路径：点击一次即可跳转到待处理会话

---

## 3. 状态模型（展示层）
状态集合：
- `running`：正在处理任务
- `waiting`：需要用户输入/确认才能继续
- `idle`：存活但当前无活跃处理
- `exited`：终端已退出

说明：
- `waiting` 是唯一高优先显著状态
- 其余状态以弱提示展示，避免信息过载

---

## 4. UI 呈现方案

### 4.1 Tab 区
- 默认仅展示：颜色点 + 名称 + 关闭按钮
- 当状态为 `waiting`：
  - 追加轻量徽标：`● waiting`
  - 温和高亮（轻底色 + 字重），不使用闪烁/强动画
- `running/idle/exited` 不做 Tab 常驻文案（降低噪音）

### 4.2 Group Header
- 显示聚合提示：`Wn`（如 `W2`）
- 仅当 `W > 0` 时轻微提亮组名
- 不展示全量 R/I/X 计数，保持组头简洁

### 4.3 StatusBar（全局主入口）
- 右侧展示全局统计：`W:n | R:n | I:n | X:n`
- `W:n` 可点击：跳转到“下一个 waiting terminal”（循环）
- 左侧 active 区显示：`<terminal-name> · <state>`

---

## 5. 关键交互

### 5.1 快速跳转（核心）
- 点击 StatusBar 的 `W:n`：
  - 若 `W=0`：无跳转，给轻反馈
  - 若 `W>0`：按可见顺序跳到下一条 waiting，会循环

### 5.2 快捷键（建议）
- `Cmd/Ctrl + ;`：执行与点击 `W:n` 相同的“下一条 waiting”跳转

### 5.3 状态刷新
- 状态变化后，Tab/Group/StatusBar 三处同步刷新
- 使用短去抖防抖动，避免视觉闪烁

---

## 6. 状态来源策略（v1）
采用旁路推断（不改用户操作习惯）：
- 输入信号：用户向 terminal 写入内容
- 输出信号：PTY 输出匹配 waiting 关键词/模式
- 时间信号：无输出静默阈值 -> `idle`
- 进程信号：PTY 退出 -> `exited`

推断优先级：
1. exited
2. waiting
3. running
4. idle

---

## 7. 成功标准（验收）
- 用户可在 1~2 次点击内定位任一 `waiting` 会话
- `W` 计数与实际待处理会话一致
- 多终端并行时，界面仍保持清爽，不出现明显噪音
- 不影响现有 tab 拖拽、分组、关闭、切换行为

---

## 8. 实施范围（v1）
包含：
- 状态模型扩展（展示层）
- StatusBar 聚合统计 + `W` 跳转
- Tab waiting 徽标与温和高亮
- Group waiting 聚合提示

不包含：
- 协议级强一致状态上报
- 桌面通知/弹窗告警
- 复杂过滤侧栏或独立状态面板

---

## 9. 后续演进（v2+）
- waiting 规则可配置（关键词词库可编辑）
- 可选“待处理列表面板”
- 可选强一致注入模式（包装器事件上报）
